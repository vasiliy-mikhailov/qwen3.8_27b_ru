# Базовая точка перед дообучением

Дата: 2026-09-23. Артефакт `qwen3_8_27b_nvfp4.ninfer`, KV `k8v4`, контекст 4096 / шаг 2048.
Один прогон — пять минут, 2 214 022 токена.

## Зачем эта страница

Дообучать без этой таблицы нельзя: не с чем сравнивать. Причём мерить надо не только цель,
но и то, что дообучение испортит. Штатный корпус ninfer уже содержит четыре домена-стража,
включая его собственный C++/CUDA-код, — то есть регрессия видна тем же инструментом, в тех же
единицах, в том же прогоне.

## Корпус для обучения

Цель — не литературный русский, а то, **как по-русски принято комментировать код и писать
о коде**. Поэтому источники подобраны по регистру, а не по объёму.

| источник | что даёт | объём | статус |

| `codeparrot/github-code`, фильтр по русским комментариям | настоящие комментарии и докстринги в живом коде | ~6 000 слов с шарда, 24 шарда скачано | собирается |

### Чего стоило внимания при сборке

**Кириллица — не русский.** На GitHub самые «плотные» попадания кириллицы — украинские файлы
локализации Qt (`bitcoin_uk.ts`), то есть таблицы переводов, а не комментарии. Фильтр
отсекает пути локализации и различает языки по буквам: `і ї є ґ` выдают украинский,
наличие `ы э ъ` подтверждает русский.

**Строковые литералы — не комментарии.** Регистр несут только комментарии и докстринги.

**`#` — не всегда комментарий.** В Markdown это заголовок. Без этой поправки в корпус
комментариев попадали строки вида «### Библейские тексты для исследования».

**`[code]` вместо кавычек.** ru.stackoverflow размечает код тегами `[code]`, которых модель
не видела; они переписаны в обычные ограждения из трёх кавычек, чтобы не учить разметке.

## Отложенная часть как метрика регистра

Десятая доля каждого источника изъята из обучения и подключена доменом
`russian_code_register`. Это и есть измеритель того, на что жалуется владелец: если модель
начинает лучше предсказывать, как люди на самом деле комментируют русский код, регистр
улучшился. Ни OOV, ни гомоглифы, ни RuBLiMP этого не видят.

## Что предсказано заранее

Записано до обучения, чтобы потом не подгонять объяснение под результат:

- OOV, гомоглифы, CJK — упадут: это дефекты покрытия, их лечит больше русского;
- `russian_code_register` — упадёт, это прямая цель;
- RuBLiMP — не сдвинется;
- `ninfer_code`, английский, китайский — вырастут, если не поставить KL-якорь к исходной
  модели на смеси кода и английского;
- долгие зависимости (согласование через длинную именную группу, связность через абзацы) —
  не улучшатся при обучении на 4k контекста, а больше на 32 ГБ не влезет.
